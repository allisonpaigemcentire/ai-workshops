r15-services-customer: Fleet View Setup

Quick reference

Repo: r15-services-customer (multi-domain: cx, rms, common, ui-admin)

Branch naming: <username>/TYP-XXXXX-<description>

Per-worktree setup: Copy .env, docker-compose.override.yaml; run domain-specific builds

Domains build independently: ./gradlew -p cx build, ./gradlew -p rms build, etc.

Per-worktree setup checklist

Files to copy (git-ignored):
  1. .env — copy from main checkout to worktree root
  2. docker-compose.override.yaml — copy or create with volume mounts
  3. Service-specific application-local.yaml files (varies per service; check README.md)
Build commands per domain (run in each worktree):
./gradlew -p cx build # if working on cx domain ./gradlew -p rms build # if working on rms domain ./gradlew -p common build # if working on common domain
For ui-admin (if applicable):
cd ui-admin && yarn install && yarn serve:dev

Exact steps: Claude CLI

  1. Start in main checkout: cd /Users/amcentire/r15-services-customer
  2. For each worktree, copy setup files and run builds (or embed in prompt)
  3. Launch three processes in parallel with setup embedded in prompts
claude --worktree task-1 "Copy .env and docker-compose.override.yaml. Run ./gradlew -p cx build. Then [task 1 on cx domain]. Commit and push to am/task-1-xxx." & claude --worktree task-2 "Copy .env and docker-compose.override.yaml. Run ./gradlew -p rms build. Then [task 2 on rms domain]. Commit and push to am/task-2-xxx." & claude --worktree task-3 "Copy .env. Then [task 3]. Commit and push to am/task-3-xxx." & wait

Track results

gh pr list --author=@me git worktree list

Notes

  • Each domain builds independently — no shared build outputs across worktrees.
  • .env and service configs are git-ignored; you must copy them.
  • Check each service's README.md in that domain directory for specific setup (e.g., cx/product/README.md).
  • Docker and Java 17 must be installed locally.
