Key Practices

Worktree Adoption Patterns

  • Worktrees are most useful for parallel work on separate branches of the same repository.
  • Teams using AI coding agents benefit most when each agent gets its own checked-out branch.
  • Directory structure matters: sibling paths (../repo-name) or tool-managed paths (.claude/worktrees/name) both work.

Common Gotchas

  • One branch cannot be checked out in two worktrees at the same time. Git enforces this automatically.
  • Worktrees share Git objects and refs but keep working files separate. Dependencies and generated files must be managed per-checkout.
  • Worktrees are not process isolation. Two apps can still compete for the same port, database, or device.
  • If a worktree directory is deleted outside of Git, git worktree prune cleans up stale metadata.

Best Practices

  • Always run git worktree list before creating a new worktree.
  • Always remove worktrees with git worktree remove, not manual directory deletion.
  • Use --detach for temporary, throwaway checkouts.
  • In Claude Code, use .worktreeinclude to copy environment files and secrets into worktrees.
  • In Cursor, automate setup in .cursor/worktrees.json and watch the machine-wide worktree cap.
