Slide 04 · Subagents

Keeping them current

Treat agent files like code: review changes, and check project agents into the repo so the team improves the same copy.

Routing

Fix the description

When an expert fires on the wrong task or never fires, rewrite its description: the domain, when to use it, an example. Then test with a few prompts.

Pointers

Refresh the paths

When docs or folders move, update the paths in the body. Claude Code reloads edited agent files within seconds, no restart needed.

Prune

Small set, not a fleet

Every description is a routing choice, so more experts means more wrong picks. Start with two or three and delete the ones you never call.

Audit

Re-run the slide 19 prompt

The audit prompt later in this deck lists ~/.claude/agents/, ~/.cursor/agents/ and ~/.gemini/agents/. Ask it which experts overlap or have gone stale.

Silent skips

Check the frontmatter

Claude Code skips a file with no name, or with a name but no description, with no message in the chat, so a typo looks like an expert that never fires.

Slide 08 · Step 2

Install the session-memory skill

For executive conversations · 20-second card

The skill is the detailed runbook: you only open it when it is time to write a lesson down. Think of it as the long checklist for one pipeline stage, not something that runs on every build. That keeps everyday chat cheap and still gives a repeatable write path when someone says wrap up.

  • Proof: Without a runbook, wrap-up becomes guesswork and people invent “lessons” that were never corrected.
  • Safety: The gate is hard: store only explicit corrections, no silent memory from noisy chat.
  • Ask: Install this skill once, then treat wrap-up as a normal close-out step after a correction.

# Session memory: personal cross-tool learnings

Machine-local durable memory for **Cursor and Claude**. Canonical store:
`~/.ai-memory/`. This is not Claude project auto-memory and not a git journal.

## When to use

| Trigger | Action |
|---------|--------|
| "done", "wrap up", "capture learnings", "update memory" | **Write** wrap-up |
| Stop-hook follow-up about session memory | **Write** wrap-up |
| User correction / “never do that again” | Mark `needs-wrapup`, then wrap up (same turn if natural) |
| "what did we learn about X?", starting related work | **Read** `MEMORY.md` + matching `lessons/` |

## Paths

| Path | Role |
|------|------|
| `~/.ai-memory/MEMORY.md` | Active lesson index (≤80 lines / ~4k chars) |
| `~/.ai-memory/lessons/<slug>.md` | One durable lesson |
| `~/.ai-memory/sessions/YYYY-MM-DD-<tool>.md` | Optional raw session note |
| `~/.ai-memory/STAGED.md` | Promotion candidates |
| `~/.ai-memory/.hooks/<conversation_id>/` | `needs-wrapup`, `wrapped-up`, `prompt-attempts` |

Conversation id: use a stable chat/conversation id when known; otherwise `unknown`.

## Write workflow

### 1. Gather only real lessons

From this chat, list:

- Explicit user corrections
- Failed approaches the user rejected
- “Do it this way next time” confirmations

**Do not invent.** If nothing qualifies, say so, clear any stale `needs-wrapup`
only if the user confirms there is nothing to store, and stop.

### 2. Dedupe / upsert lessons

For each lesson:

1. Scan `~/.ai-memory/lessons/*.md` and `MEMORY.md` for near-duplicates.
2. If a match exists: update that file (`last_seen`, body). Keep `status: active`.
3. If new: create `lessons/<slug>.md` with kebab-case slug.

Lesson file template:

```markdown
---
slug: example-slug
status: active
created: YYYY-MM-DD
last_seen: YYYY-MM-DD
repos: [optional-repo-name]
---

# Short title

## Lesson

When X, never Y / always Z.

## When

Context where this applies.

## Do / Don't

- …
```

Prefer **negative constraints** over narrative.

### 3. Refresh `MEMORY.md`

- One bullet per **active** lesson: short constraint + markdown link to the lesson file.
- Remove bullets for `status: archived` lessons.
- Enforce the size budget in `MEMORY.md`. If over budget, archive the least
  recently seen or least actionable lesson (set `status: archived`, drop bullet).

### 4. Optional session note

Append or create `sessions/YYYY-MM-DD-cursor.md` or `…-claude.md` with 2 to 5 lines
summarizing what was stored. Append-only; do not rewrite older session files.

### 5. Promotion ladder

| Kind | Action |
|------|--------|
| Personal never-again | Done after steps 2 to 3 |
| Personal workflow habit (draft PRs, commit gates, shorthand) | Propose edit under `~/.cursor/rules/`; remind user to run `bash ~/.agents/scripts/sync-personal-rules.sh` |
| Repo / team convention | Append a row to `STAGED.md`; ask before editing that repo’s `AGENTS.md` |

### 6. Clear stop-nudge markers

After a successful wrap-up (including “nothing to store” confirmed by user):

```bash
CONV_ID="<conversation_id_or_unknown>"
DIR="$HOME/.ai-memory/.hooks/$CONV_ID"
mkdir -p "$DIR"
rm -f "$DIR/needs-wrapup"
printf '%s\n' "$(date -u +%Y-%m-%dT%H:%M:%SZ)" > "$DIR/wrapped-up"
```

Do not commit `~/.ai-memory/` anywhere unless the user explicitly asks.

## Mark correction (without full wrap-up yet)

When you must defer wrap-up:

```bash
CONV_ID="<conversation_id_or_unknown>"
DIR="$HOME/.ai-memory/.hooks/$CONV_ID"
mkdir -p "$DIR"
printf '%s\n' "correction noted" > "$DIR/needs-wrapup"
rm -f "$DIR/wrapped-up"
```

## Load / search

1. Read `~/.ai-memory/MEMORY.md`.
2. Open linked lesson files as needed.
3. For keyword search: `rg -i '<query>' ~/.ai-memory/lessons ~/.ai-memory/MEMORY.md`.

## Output to the user

After wrap-up, report briefly:

- Lessons added / updated (slugs)
- Whether anything was staged for promotion
- Reminder to re-run personal-rules sync if a `~/.cursor/rules/` file changed

Slide 10 · Step 3

Install the always-on Cursor rule

For executive conversations · 20-second card

The rule is the standing order that rides with every chat: load past lessons, mark a correction when it happens, and call the runbook at wrap-up. Same idea as a lint gate that always runs: small, always on, and it tells you when to open the longer checklist. You need both: the gate alone has no write procedure; the runbook alone never gets opened unless someone remembers.

  • Proof: Without an always-on standing order, Cursor and Claude forget last week’s “never do that again.”
  • Safety: Blast radius stays personal: lessons live on the engineer’s machine until a human promotes a team convention.
  • Ask: Keep this rule always on, and re-run the rules sync after you add or remove personal rule files.
Don’t sayDo say
alwaysApply rule / session-memory.mdcA standing order that loads with every conversation
needs-wrapup marker / stop hookA sticky note that the close-out checklist still needs to run

install.sh copies this rule to ~/.agents/rules/session-memory.mdc, links it into ~/.cursor/rules/, and the sync mirrors it to ~/.claude/rules/session-memory.md. By hand: write it there and link it the same way. Cursor loads that folder only for projects under your home folder. For other projects, paste the rule body (below the second ---) into Customize > Rules > User Rules, next to the personal rule from install.sh --print-user-rule.

~/.agents/rules/session-memory.mdc
---
description: Load and update personal cross-tool session memory (~/.ai-memory)
alwaysApply: true
---

# Session memory (Local Only)

This rule is **local to this machine** (`~/.agents/rules/`, linked into
`~/.cursor/rules/`) and applies across all repos. Claude mirrors it via
`~/.agents/scripts/sync-personal-rules.sh`. It needs the `session-memory` skill and the
stop hooks in `~/.cursor/hooks/` and `~/.claude/hooks/`; drop this rule if you do not use them.

Create the store once: `mkdir -p ~/.ai-memory/lessons ~/.ai-memory/sessions ~/.ai-memory/.hooks`,
then add `MEMORY.md` and `STAGED.md` (starter text: `companion/personal-session-memory-setup.html`, step 1).
Never share or commit `~/.ai-memory/`.

## Canonical store

`~/.ai-memory/`: personal, machine-local. Not Claude project auto-memory and
not git-tracked journals.

| Path | Role |
|------|------|
| `~/.ai-memory/MEMORY.md` | Distilled active-lesson index (always load) |
| `~/.ai-memory/lessons/*.md` | One durable lesson per file |
| `~/.ai-memory/sessions/` | Optional raw wrap-up notes |
| `~/.ai-memory/STAGED.md` | Promotion candidates (human review) |
| `~/.ai-memory/.hooks/` | Stop-nudge markers (do not invent lessons here) |

## Load (every session)

1. **Read** `~/.ai-memory/MEMORY.md` early in the session (or before acting on
   a task that could repeat a past mistake class).
2. Obey active lessons. Open linked `lessons/<slug>.md` when the one-liner is
   not enough.
3. Keep the index under its documented size budget when you edit it.

## Mark corrections

When the user corrects you (or you discover a durable “never do X again”):

1. Resolve a conversation id if available (`conversation_id` / chat id from the
   environment or hook payload). If unknown, use `unknown`.
2. Ensure `~/.ai-memory/.hooks/<conversation_id>/` exists.
3. Write or touch `needs-wrapup` in that directory (content can be a one-line
   reason). Do **not** invent a full lesson yet. Wait for wrap-up.

## Wrap-up triggers

Run the **`session-memory`** skill (read `~/.agents/skills/session-memory/SKILL.md`,
linked at `~/.cursor/skills/` and `~/.claude/skills/`) when any of these happen:

- User says **done**, **wrap up**, **capture learnings**, or **update memory**
- Stop-hook follow-up asks you to update session memory
- You are about to end a session that has a `needs-wrapup` marker

## Write rules

- Never invent lessons. Only write what the user corrected or explicitly confirmed.
- Prefer negative constraints: “when X, never Y / always Z.”
- Deduplicate against existing `lessons/` before adding a new slug.
- After a successful wrap-up, remove `needs-wrapup` and write `wrapped-up` for
  that conversation id so the stop nudge stays quiet.

## Promotion ladder (do not dump everything into always-on rules)

| Kind | Destination |
|------|-------------|
| Personal “never do X again” | `~/.ai-memory/lessons/` + `MEMORY.md` |
| Personal workflow habit | Propose `~/.cursor/rules/*.mdc` + remind to run `~/.agents/scripts/sync-personal-rules.sh` |
| Repo / team convention | Ask before editing that repo’s `AGENTS.md`; stage in `STAGED.md` if unsure |

## Do not

- Treat Claude `~/.claude/projects/*/memory/` as the shared store
- Auto-commit learnings into shared repos without explicit user instruction
- Grow `MEMORY.md` past its size budget

~/.agents/scripts/sync-personal-rules.sh (complete)
#!/usr/bin/env bash
# Mirror ~/.cursor/rules/*.mdc into Claude. install.sh runs this for Claude Code;
# re-run it after adding or removing a rule file (shared.md is wired separately).
#
# Canonical for this bridge: ~/.cursor/rules/*.mdc
# Claude:    ~/.claude/rules/<stem>.md  -> symlink to each .mdc
# Exclude:    ~/.cursor/rules/.claude-exclude (stems to skip)
# Index:     ~/.claude/CLAUDE.md        (only if missing or managed by this script;
#            never once wire-personal-agents.sh manages it)
#
# Usage:
#   bash ~/.agents/scripts/sync-personal-rules.sh          # create/update links
#   bash ~/.agents/scripts/sync-personal-rules.sh --check  # report drift; exit 1 if out of sync
#   bash ~/.agents/scripts/sync-personal-rules.sh --help

set -euo pipefail

CURSOR_RULES="${CURSOR_RULES:-$HOME/.cursor/rules}"
CLAUDE_RULES="${CLAUDE_RULES:-$HOME/.claude/rules}"
CLAUDE_MD="${CLAUDE_MD:-$HOME/.claude/CLAUDE.md}"
CLAUDE_EXCLUDE="${CLAUDE_EXCLUDE:-$CURSOR_RULES/.claude-exclude}"
MANAGED_MARKER="<!-- managed-by: sync-personal-rules -->"
# wire-personal-agents.sh owns CLAUDE.md once it has added its region; never
# rewrite that file, or the @-import of shared.md is lost.
WIRE_MARKER="<!-- managed-by: wire-personal-agents -->"

MODE="sync"
for arg in "$@"; do
  case "$arg" in
    --check) MODE="check" ;;
    -h|--help)
      sed -n '2,14p' "$0" | sed 's/^# \{0,1\}//'
      exit 0
      ;;
    *)
      echo "Unknown argument: $arg (try --help)" >&2
      exit 2
      ;;
  esac
done

added=0
removed=0
updated=0
missing=0
conflicts=0
drift_msgs=()

# --check only reports; it must not create anything.
if [[ "$MODE" != "check" ]]; then
  mkdir -p "$CLAUDE_RULES"
fi

# Resolve absolute path for symlink targets (portable; no GNU realpath required).
abs_path() {
  local path="$1"
  local dir base
  dir="$(cd "$(dirname "$path")" && pwd)"
  base="$(basename "$path")"
  printf '%s/%s\n' "$dir" "$base"
}

stem_of_mdc() {
  local base
  base="$(basename "$1")"
  printf '%s\n' "${base%.mdc}"
}

link_path_for_stem() {
  printf '%s/%s.md\n' "$CLAUDE_RULES" "$1"
}

desired_target_for_mdc() {
  abs_path "$1"
}

is_excluded() {
  local stem="$1"
  local line
  [[ -f "$CLAUDE_EXCLUDE" ]] || return 1
  while IFS= read -r line || [[ -n "$line" ]]; do
    line="${line%%#*}"
    line="$(printf '%s' "$line" | sed 's/^[[:space:]]*//;s/[[:space:]]*$//')"
    [[ -n "$line" ]] || continue
    if [[ "$line" == "$stem" ]]; then
      return 0
    fi
  done <"$CLAUDE_EXCLUDE"
  return 1
}

# Step 1: remove broken symlinks under Claude rules that this script made
# (they point into the Cursor rules folder). Other links are left alone.
shopt -s nullglob
for link in "$CLAUDE_RULES"/*; do
  [[ -L "$link" ]] || continue
  case "$(readlink "$link")" in "$CURSOR_RULES"/*) ;; *) continue ;; esac
  if [[ ! -e "$link" ]]; then
    if [[ "$MODE" == "check" ]]; then
      drift_msgs+=("broken symlink: $link")
      ((missing++)) || true
    else
      rm "$link"
      ((removed++)) || true
    fi
  fi
done

# Step 1b: remove symlinks for excluded stems.
for link in "$CLAUDE_RULES"/*.md; do
  [[ -L "$link" ]] || continue
  stem="$(basename "$link" .md)"
  if is_excluded "$stem"; then
    if [[ "$MODE" == "check" ]]; then
      drift_msgs+=("excluded stem still linked: $link")
      ((missing++)) || true
    else
      rm "$link"
      ((removed++)) || true
    fi
  fi
done

# Step 2: ensure each Cursor .mdc has a Claude .md symlink (unless excluded).
declare -a linked_stems=()
for mdc in "$CURSOR_RULES"/*.mdc; do
  [[ -f "$mdc" ]] || continue
  stem="$(stem_of_mdc "$mdc")"
  if is_excluded "$stem"; then
    continue
  fi
  link="$(link_path_for_stem "$stem")"
  target="$(desired_target_for_mdc "$mdc")"
  linked_stems+=("$stem")

  if [[ -e "$link" || -L "$link" ]]; then
    if [[ -L "$link" ]]; then
      current="$(readlink "$link" || true)"
      # Normalize relative readlink results against CLAUDE_RULES.
      if [[ "$current" != /* ]]; then
        current="$(cd "$CLAUDE_RULES" && abs_path "$current")"
      fi
      if [[ "$current" == "$target" ]]; then
        continue
      fi
      if [[ "$MODE" == "check" ]]; then
        drift_msgs+=("wrong target: $link -> $current (want $target)")
        ((missing++)) || true
      else
        ln -sfn "$target" "$link"
        ((updated++)) || true
      fi
    else
      # Real file: never overwrite.
      drift_msgs+=("conflict (not a symlink, left alone): $link")
      ((conflicts++)) || true
    fi
    continue
  fi

  if [[ "$MODE" == "check" ]]; then
    drift_msgs+=("missing link: $link -> $target")
    ((missing++)) || true
  else
    ln -sfn "$target" "$link"
    ((added++)) || true
  fi
done

# Step 3: managed CLAUDE.md index (sync only; check reports if managed and stale).
should_write_claude_md=0
if [[ ! -f "$CLAUDE_MD" ]]; then
  should_write_claude_md=1
elif grep -qxF "$WIRE_MARKER" "$CLAUDE_MD" 2>/dev/null; then
  should_write_claude_md=0
elif grep -qF "$MANAGED_MARKER" "$CLAUDE_MD" 2>/dev/null; then
  should_write_claude_md=1
fi

write_claude_md() {
  local stem link mdc
  {
    printf '%s\n' "$MANAGED_MARKER"
    cat <<'EOF'
# Personal Claude instructions (local only)

These preferences apply across projects on this machine. Canonical copies live
in `~/.cursor/rules/`; this Claude setup mirrors them via symlinks under
`~/.claude/rules/`.

Regenerate this file with `scripts/sync-personal-rules.sh` from the
repo that ships this script (or your local copy).

## Precedence

Repo `AGENTS.md`, `.agents/skills/`, repo hooks, and repo rules win over
personal prefs. On conflict, follow the repo. Personal files are how you like
answers, commits, and PRs, not how to build a given tree.

## Mirrored personal rules

Claude loads every file in `~/.claude/rules/` at session start. Edit the Cursor
sources; the Claude links update automatically. After **adding or removing** a
Cursor rule file, re-run the sync script. Stems listed in
`~/.cursor/rules/.claude-exclude` are not mirrored (Claude ignores
`alwaysApply: false`; exclude situational Cursor-only rules there).

| Rule | Source |
|------|--------|
EOF
    for stem in "${linked_stems[@]:-}"; do
      [[ -n "$stem" ]] || continue
      mdc="$CURSOR_RULES/${stem}.mdc"
      printf '| `%s` | `%s` |\n' "$stem" "$mdc"
    done
    cat <<'EOF'

## Situational rules (Cursor-only sources)

Stems in `.claude-exclude` do not load every session. When the task matches,
**read the full Cursor source file** under `~/.cursor/rules/` before you act
(for example a long PR-authoring rule: read it only when you draft, create, or
update a PR).

## Cross-tool session memory

Personal durable learnings live in `~/.ai-memory/MEMORY.md` (not Claude project
auto-memory under `~/.claude/projects/*/memory/`). At session start, **read**
that file. On wrap-up / corrections, use the `session-memory` skill
(`~/.claude/skills/session-memory` → `~/.agents/skills/session-memory`), if installed.

## Notes

- Cursor frontmatter (`alwaysApply`, `globs`, `description`) is harmless noise
  for Claude; follow the markdown body.
- Repo-shared conventions still come from each project’s `AGENTS.md` /
  `CLAUDE.md` when working in that repo.
- To confirm load: in Claude Code run `/memory` or `/context` and check
  Memory / rules files.
EOF
} >"$CLAUDE_MD"
}

if (( should_write_claude_md )); then

Slide 14 · Stop hook Python

Full session-memory-stop.py

~/.cursor/hooks/session-memory-stop.py
#!/usr/bin/env python3
"""Cursor stop hook: nudge session-memory wrap-up after corrections (capped).

Fails open. Never invents or writes lessons, only optionally returns
followup_message so the agent runs the session-memory skill.
"""

from __future__ import annotations

import json
import re
import os
import sys
from pathlib import Path

MAX_PROMPT_ATTEMPTS = 2
MEMORY_ROOT = Path.home() / ".ai-memory"
HOOKS_ROOT = MEMORY_ROOT / ".hooks"
SAFE_ID = re.compile(r"^[A-Za-z0-9_-][A-Za-z0-9._-]{0,127}$")

FOLLOWUP = (
    "A correction was marked earlier in this chat and session memory was not "
    "updated yet. Run the session-memory skill now: read "
    "~/.cursor/skills/session-memory/SKILL.md, capture durable lessons into "
    "~/.ai-memory/, refresh MEMORY.md, and clear the needs-wrapup marker for "
    "this conversation. Do not invent lessons. Only store what the user "
    "corrected or confirmed."
)


def _conversation_id(payload: dict) -> str | None:
    for key in (
        "conversation_id",
        "conversationId",
        "session_id",
        "sessionId",
        "chat_id",
        "chatId",
        "composerId",
        "composer_id",
    ):
        value = payload.get(key)
        if isinstance(value, str) and value.strip():
            return value.strip()
    # Nested common shapes
    for nest in ("conversation", "session", "composer"):
        block = payload.get(nest)
        if isinstance(block, dict):
            for key in ("id", "conversation_id", "session_id"):
                value = block.get(key)
                if isinstance(value, str) and value.strip():
                    return value.strip()
    return None


def _read_attempts(conv_dir: Path) -> int:
    path = conv_dir / "prompt-attempts"
    if not path.is_file():
        return 0
    try:
        return int(path.read_text(encoding="utf-8").strip() or "0")
    except (OSError, ValueError):
        return 0


def _bump_attempts(conv_dir: Path) -> None:
    conv_dir.mkdir(parents=True, exist_ok=True)
    attempts = _read_attempts(conv_dir) + 1
    (conv_dir / "prompt-attempts").write_text(f"{attempts}\n", encoding="utf-8")


def main() -> int:
    try:
        raw = sys.stdin.read()
        payload = json.loads(raw) if raw.strip() else {}
    except json.JSONDecodeError:
        print("{}")
        return 0

    if not isinstance(payload, dict):
        print("{}")
        return 0

    status = payload.get("status") or "completed"
    if status != "completed":
        print("{}")
        return 0

    try:
        loop_count = int(payload.get("loop_count") or 0)
    except (TypeError, ValueError):
        loop_count = 0
    if loop_count >= 1:
        # Already in a follow-up loop from a prior nudge: stay quiet.
        print("{}")
        return 0

    conv_id = _conversation_id(payload)
    # The id becomes a folder name under ~/.ai-memory/.hooks; refuse anything
    # that could point outside it (a slash, "..", a leading dot).
    if not conv_id or not SAFE_ID.match(conv_id):
        print("{}")
        return 0

    conv_dir = HOOKS_ROOT / conv_id
    needs = conv_dir / "needs-wrapup"
    wrapped = conv_dir / "wrapped-up"

    if wrapped.is_file() or not needs.is_file():
        print("{}")
        return 0

    if _read_attempts(conv_dir) >= MAX_PROMPT_ATTEMPTS:
        print("{}")
        return 0

    try:
        _bump_attempts(conv_dir)
    except OSError:
        print("{}")
        return 0

    print(json.dumps({"followup_message": FOLLOWUP}))
    return 0


if __name__ == "__main__":
    try:
        raise SystemExit(main())
    except Exception:  # noqa: BLE001 (hooks must fail open)
        print("{}")
        raise SystemExit(0)

Slide 17 · Borrowed practice

Match the model to the work

Pin tiers, not versions. Pick the cheapest tier that clears the bar, and escalate per task, not for the whole session.

TierSend itClaude CodeCursorGemini CLI
DeepArchitecture, plans, review, correctness-critical reasoningopusYour strongest modelpro
WorkhorseScoped code and doc writing, reading and summarizingsonnetA mid-tier model, or Composerflash
Fast"Where is X?", breadth search, mechanical scanshaikuComposer, or the Explore subagentflash-lite
Keep context lean

Every turn resends the whole chat, so early file reads cost you until the session ends. Let the main chat plan, send long reads to a subagent that returns a short digest, and start a new chat or /clear at phase boundaries.

Cursor caveats

Legacy request-based plans without Max Mode run subagents on Composer, whatever model: says. Subagents cost extra: Cursor's docs say five in parallel use "roughly five times the tokens of a single agent", so use helpers for long reads only.

Read-only helpers that cite file and line

examples/agents/code-reader.md

code-reader

Explains one file, module or PR diff: summary, structure, entry points and key functions, each with path:line. Describes, never judges.

examples/agents/doc-reader.md

doc-reader

Answers one question from a long doc, spec or web page: a direct answer, cited detail, and what the doc does not cover.

The reading happens once, in a throwaway context. Only the digest comes back, and the citations let you spot-check it. Off by default: add --with-helpers to the install command. It installs both for each tool in --tools, backs up any file of yours with the same name, and uninstall puts it back.
