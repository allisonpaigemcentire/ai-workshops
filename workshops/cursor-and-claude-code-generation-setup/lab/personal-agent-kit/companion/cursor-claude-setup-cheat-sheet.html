How to set up Cursor and Claude for better code generation

One personal folder, ~/.agents/, feeds Cursor, Claude Code and Gemini CLI, so all three follow the same preferences. The repo always wins over it. A few small rules and hooks stop the agents from pushing, committing or burning context without you asking.

Training: Mon Nov 2, 4:30 to 5:00 PM ET
Supported tools: Cursor, Claude Code, Gemini

1What the kit is

  • You do not need it to start. Repo skills and Cursor Cloud work with no setup. The kit is optional, for people who use more than one AI tool on their own machine.
  • You edit one file, ~/.agents/instructions/shared.md. A wire script writes a thin wrapper into each tool's home folder.
  • Personal files say how you like answers, commits and PRs. They never say how to build, test, branch or lint a repo. The repo owns that.

2Who wins on a conflict

  1. What you type in this chat turn.
  2. The repo: nearest AGENTS.md, .agents/skills/, repo hooks and rules.
  3. Thin repo adapters (CLAUDE.md pointing to AGENTS.md, .gemini/settings.json).
  4. Personal: ~/.agents/instructions/shared.md and its wrappers.
  5. Model defaults.

Cursor Cloud agents do not load these personal files. They only see the repo.

4Install (one command)

Download personal-agent-kit-v2.zip, unzip it into ~/src, then run:

mkdir -p ~/src && unzip ~/Downloads/personal-agent-kit-v2.zip -d ~/src
bash ~/src/personal-agent-kit/scripts/install.sh

It shows a preview, asks once, then installs: copies the kit into ~/.agents/, links rules, hooks and the status line, writes the Cursor, Claude Code and Gemini wrappers, and merges the hooks, status line and MCP servers into your config files. It backs up every file first (~/.agent-kit-backups/), adds only what is missing and is safe to re-run. Preview only: add --dry-run.

5Then finish

  1. Fill in the <placeholders> in ~/.agents/instructions/shared.md, then re-run the install command.
  2. Start a new chat in each tool. In Gemini CLI, trust your project folder or MCP servers stay off.
  3. Optional: turn on code intelligence (LSP). See docs/enable-lsp.md.
  4. Undo any time: bash ~/.agents/scripts/uninstall.sh

6Guardrails built in

  • No commit, push, PR open or close, or branch delete unless you asked in that turn. "Looks good" is not a yes.
  • Push gate: before any push the agent scans for leftover REVIEW(context): notes and refuses until they are gone.
  • --no-verify only when every lint failure predates your diff. New failures get fixed.
  • Hooks fail open: a broken hook never blocks work. The memory stop nudge is capped at two tries.
  • No tokens in config files. Use OAuth, ${env:VAR}, or scripts/mcp-env-from-keychain.sh.

Text rules only advise. Hooks and permission deny lists enforce. Do not allow-list git push or gh pr create in tool permissions. git -C <path> slips past prefix rules, so test every guard with a known-bad input. Model tiers and more: docs/borrowed-practices.md.

7Why long sessions degrade

  • Everything always-on loads into every chat: shared.md, always-apply rules, and the description of every MCP tool you have connected.
  • A long chat also carries every earlier turn and file read forward, so each new answer costs more.
  • The optional Cursor cost guard nudges you once to start a fresh chat past 25 turns or 15M input tokens. It only works with the Span hook log and stays silent without it.

UNVERIFIED How much answer quality drops in a long session. The kit sets nudge points, not measured limits.

8Keep context lean

  • Keep always-on files short. Put long, task-specific rules on request.
  • Claude ignores alwaysApply: false, so list situational rules in rules/.claude-exclude.
  • Let the main chat plan. Send exploration and huge-file reads to a subagent or second session that returns a short finding.
  • Start a new chat or /clear at phase boundaries.
  • Use a cheaper model for mechanical edits.
  • Prefer CLI-backed skills over MCP servers for reads.
  • Watch the Claude status line: model, branch, PR and context %.

9Quick commands and habits

# the push-gate scan
git grep -n 'REVIEW(context):' || true
  • Confirm prefs loaded: /memory in Claude, /memory show in Gemini, a quote test in Cursor.
  • Every change: investigate, plan, write, then run the repo's own build, test and lint.
  • You own every line you ship. If you cannot explain a change, ask the agent to walk you through it or cut it.
