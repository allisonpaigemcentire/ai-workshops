Slide 03 · Subagents

What a subagent is: its own context, a short answer back

Own context

The reading stays out of your chat

Each subagent has its own context window, so long research or exploration does not use up space in your main conversation.

Clean start

It does not see your chat

It starts with a clean context. The main agent writes its task, so say what matters: the goal, the paths, the limits.

Short answer

Only the final message comes back

The subagent works on its own and returns its result. Ask for bullets with path:line so you can check them.

Not free

It spends tokens too

Its requests count toward your usage. Five subagents in parallel use roughly five times the tokens of one agent.

Claude Code~/.claude/agents/.claude/agents/
Cursor~/.cursor/agents/.cursor/agents/

Cursor also reads .claude/agents/ folders. When two files share a name, the one in .cursor/ wins.

Slide 05 · Subagents

Install them with one command

shell · unzip once, preview, install
mkdir -p ~/src && unzip ~/Downloads/subagent-starter-kit.zip -d ~/src
bash ~/src/subagent-starter-kit/install.sh --dry-run
bash ~/src/subagent-starter-kit/install.sh
shell · later: check, or undo
bash ~/src/subagent-starter-kit/install.sh --check
bash ~/.subagent-starter-kit/uninstall.sh

Only Cursor or only Claude Code? Add --tools=cursor or --tools=claude.

  1. It previews every change and asks once--dry-run stops after the preview. --yes skips the question.
  2. It copies three files per toolInto ~/.claude/agents/ and ~/.cursor/agents/, and nowhere else.
  3. Your files are safeA same-name file that is yours is left alone. --force replaces it after a backup in ~/.subagent-starter-kit/backups/.
  4. Safe to re-runIt updates only the kit's own unchanged copies, and says "Nothing to change." when you are current.
  5. Load themClaude Code: restart once if ~/.claude/agents/ is new. Cursor: if one does not show up yet, start a new chat.

Slide 06 · Subagents

Using them: /name in Cursor, @agent-name in Claude Code, or plain words

prompt · Cursor
/context-checker check my current branch against this repo's AGENTS.md, CLAUDE.md and skills before I open the PR.
prompt · Claude Code (or type @ and pick "context-checker (agent)")
@agent-context-checker check my current branch against this repo's AGENTS.md, CLAUDE.md and skills before I open the PR.
prompt · either tool, plain words
Use the code-reader subagent to explain src/billing/invoice.ts.
Goal: I need to change how totals are rounded.
Limits: read-only; skip generated files.
Return: a summary, then bullets with path:line.
Pick it

Name it to be sure

In Claude Code an @-mention guarantees that subagent runs for the task. Plain words let the main agent decide.

Brief it

Write it like a ticket

Goal, paths to read, limits, and the shape of the answer you want back.

Fan out

Run them in parallel

Independent questions can go to several subagents at once in both tools.

Check it

Open a cited line

Spot-check a path:line before you edit, commit or reply on the strength of the answer.

In Claude Code, subagents are not slash commands. Typing @agent- shows file matches as you type, but the mention still resolves when you send it.

Slide 07 · Subagents

How routing works: the description decides

When you do not name a subagent, the main agent compares your task with each description and delegates when one matches.

Vague

Gives no signal

description: Helps with code. The agent cannot tell when to use it, so it rarely fires, or fires on the wrong task.

Specific

Says what and when

description: Use proactively for read-only explanation of a specific file, module or PR diff. Returns a short digest that cites file and line.

"Use proactively"

Both tools document this phrase in the description as a way to encourage automatic delegation.

Test it

Try a few prompts and check that the right subagent gets picked. Rewrite the description if not.

Fewer is clearer

Every description is a routing choice. Start with two or three focused subagents and add more only for distinct jobs.

Slide 08 · Subagents

Maintaining them: edit, reload, keep two or three

An agent file is plain Markdown. Treat it like code: review changes, and check project agents into the repo so the team improves the same copy.

Edit

Change the file

Fix the description when routing is wrong. Update paths in the body when docs or folders move. Keep the prompt short and direct.

Reload

When edits take effect

Claude Code notices edits within a few seconds, with no restart, except after creating a new agents folder. Cursor: start a new chat if the change does not show.

Prune

A small set, not a fleet

Delete the ones you never call. Dozens of vague subagents are hard to route and hard to maintain.

Kit update

Re-run the installer

It replaces only the kit's own unchanged copies. A copy you edited is reported as yours and left alone.

Two copies

Keep them in step

The kit ships one copy per tool. When you edit one, edit its twin, or the tools drift apart.

Auditing them: --check and the audit prompt

shell · read only
bash ~/src/subagent-starter-kit/install.sh --check
It reportsMeaning
okThe kit's copy is in place and current
DRIFTMissing, or the kit's older copy: re-run the install
yoursYou changed it, or it is not the kit's: left alone
LINTA frontmatter problem in any agent file

Claude Code skips an agent file with no name, a name but no description, a --- that is not on line 1, or YAML that does not parse, and says nothing in the chat. The lint catches those. For a full parse: claude plugin validate ~/.claude/agents (v2.1.233 or later).

prompt · audit (prompts/audit-subagents.md)
Review my subagents, read-only, and tell me what to fix or prune.
Use a subagent for the reading if you can, to keep this chat small.
Read ~/.claude/agents/ and ~/.cursor/agents/, plus .claude/agents/ and
.cursor/agents/ in this repo if they exist. Do not scan the rest of my disk.
Never print a token or other secret value.

For each agent file, check:
- Frontmatter: --- on line 1, a name in lowercase with hyphens, and a
  description. Claude Code skips a file without them and says nothing in the
  chat, so it looks like an agent that never fires.
- Description: does it say what the agent does and when to use it? Flag
  vague ones such as "helps with code".
- Overlap: which two agents would compete for the same task?
- Paths: does the body point at files or folders that no longer exist?
- Limits: is an agent meant to be read-only actually limited? That is
  tools: Read, Grep, Glob in Claude Code and readonly: true in Cursor.
- Copies: where a Claude Code and a Cursor copy share a name, have they
  drifted apart?
- Use: which ones might I never call? Ask me rather than guess.

Give me a ranked shortlist of at most 5 changes, highest impact first, each
with the file and line. Change nothing until I pick. Show a diff before
editing any file. Never commit or push.

Slide 10 · Part 2

Why long sessions get worse, and how to keep context lean

What the research and the tool docs say, what fills your context, and five habits that keep answers sharp and costs down.

Slide 11 · Lean context

Why long sessions get worse

Context rot

More tokens, weaker recall

"As the number of tokens in the context window increases, the model's ability to accurately recall information from that context decreases." It is "a performance gradient rather than a hard cliff." Anthropic, 2025

18 models

Length alone hurts

"Model performance consistently degrades with increasing input length." "Even a single distractor reduces performance." A focused prompt of about 300 tokens beat the full 113k-token history. Chroma, 2025

Early evidence

Lost in the middle

Accuracy was highest when the key fact sat at the start or end of the input, and "significantly degrades" in the middle. Liu et al., 2023 models

In the tools

Summaries lose detail

When the window fills, both tools summarize older turns. Claude Code: "detailed instructions from early in the conversation may be lost." Cursor: after many summaries "the context accumulates noise."

Windows are bigger now. Claude Code's own docs say running out of context "is rarely the problem anymore". The reason to stay lean is better answers and lower cost.

Slide 12 · Lean context

A wrong turn sticks

"When LLMs take a wrong turn in a conversation, they get lost and do not recover." Spreading a task over many turns cost an average of 39% across six tasks. Laban et al., 2025

Two strikes

Then start fresh

Claude Code's advice: after two failed corrections, /clear and write a better prompt. A third correction mostly adds to a chat that already holds two failed attempts.

Cursor

Watch for the signs

Start a new conversation when the agent "seems confused or keeps making the same mistakes", or when you move to a different task.

Carry it over

Consolidate, then restart

The paper's tip: ask the model to consolidate everything you told it, then bring that into a new conversation.

prompt · before you start over
Please consolidate everything I've told you so far into one short brief: the goal, the constraints, what we tried and why it failed, and the files that matter. I will paste it into a new chat.

Start fresh when

The task changes

A different task or feature, one logical unit of work is done, or the agent keeps repeating a mistake.

Keep going when

The work builds on itself

You are iterating on the same feature, the agent needs earlier context, or you are debugging what it just built.

In Claude Code, /clear costs nothing and /compact reads the conversation it summarizes. A "# Compact instructions" section in CLAUDE.md sets what every compaction keeps.

Slide 15 · Lean context

Send exploration to a subagent, read only what you need

Isolate

Noisy work goes elsewhere

Cursor built its Explore and Browser subagents from "analysis of agent conversations where context window limits were hit". A subagent may read tens of thousands of tokens and return a summary of often 1,000 to 2,000.

Scope

Name the file you know

"If you know the exact file, tag it." "Including irrelevant files can confuse the agent." Vague requests such as "improve this codebase" trigger broad scanning.

Good fits

Long output you will not reread

A full test run, a wide search, a log file or a long doc. Ask for a short summary back.

Trade-off

Not for quick tasks

Each subagent starts fresh and spends its own tokens. Many detailed results can still fill your main chat.

Slide 16 · Lean context

Short rules, short AGENTS.md, a handoff note before you start fresh

Always-on files

Every line costs attention

Claude Code: aim for under 200 lines per CLAUDE.md; "longer files consume more context and reduce adherence." Cursor: keep rules under 500 lines and split large ones.

Load on demand

Scope the rest

Use path-scoped rules, skills or nested AGENTS.md for guidance that applies to part of the repo. Reference files instead of copying them in.

prompt · handoff note before a new chat
Write a handoff note to HANDOFF.md for a fresh chat. Include the goal, what is done, what is left, the decisions and why, the exact commands and errors that matter, and the files to read first. Keep it under 40 lines. Do not commit it.

Then open a new chat and point it at the note. Claude Code's docs suggest the same pattern with a spec: write it, then start a fresh session to build from it.

Done

Keep the main chat for decisions. Send the reading to a subagent.

A new chat per task, /clear or /compact with a focus when it grows, short always-on files, and a handoff note when you start over.
