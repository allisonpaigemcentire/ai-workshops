03 Practice

Repo files win.

The practice

If a personal preference and the application repo disagree, follow the repo. Personal files fill gaps on this laptop. They do not replace AGENTS.md, repo skills, repo hooks, or repo rules.

Why

The clone is what teammates and Cloud Agents see. A laptop file that fights the repo trains the agent to ignore the team harness. The Precedence block is how we say that in every personal file, because markdown cannot enforce it.

Sources

agents.md — nearest AGENTS.md wins Cursor Rules — Team → Project → User

## Precedence

Repo `AGENTS.md`, `.agents/skills/`, repo hooks,
and repo rules win.
These lines are personal prefs for this machine.
On conflict, follow the repo.

04 Practice

Hooks stop. Markdown advises.

The practice

A personal rule cannot turn off a repo hook. AGENTS.md will not return deny. Confirm-before-push in shared.md is extra advice when the repo already asks or denies.

Why

If markdown could disable a hook, a laptop pref would punch a hole in team safety. The stop lives in the product: Cursor hooks.json, Claude deny/ask, Firebender hooks. Personal files stay advisory.

06 Practice

Put ~/.agents in git.

The practice

Treat ~/.agents as a personal git tree so a new laptop can reinstall. Private remote only. Never commit secrets. This is not a team repo.

Why

Without git, the one-file setup dies on the next machine. A public remote would publish prefs and, if you slip, tokens. .gitignore is the gate. Wrappers under ~/.claude and ~/.cursor stay outside this tree unless you add them on purpose.

07 Practice

Point tools at it. Do not copy by hand.

The practice

The wire script writes wrappers. Claude @-imports shared.md (live). Cursor, Gemini, and Firebender embed a copy. Those three are stale until you re-run. Use @~/path only on the laptop. In a repo, CLAUDE.md points at AGENTS.md in that tree.

Why

Pasting the same paragraph into three home folders drifts. Claude documents @~/path for a file outside CLAUDE.md. Cursor @filename is a workspace reference, not a home import, so we embed. A @~/.agents line in a frontend or services repo would not load on Cloud or for teammates.

08 Practice

Cloud does not see your laptop.

The practice

If a preference must apply on a Cloud Agent run, put it in the repo harness or Team Rules before you start. Do not symlink ~/.agents into a repo.

Why

Desktop and Cloud are different runtimes. The Cloud VM clones the repo. It never loads ~/.agents or ~/.cursor/rules. A symlink would either fail for teammates or turn personal prefs into an accidental team contract.

Sources

Cursor Cloud Agent setup Cursor Rules — project rules travel with the clone

Example

example/home-agents/README.md

## Do not

- Commit tokens, `.env`, or keys.
- Push this tree to a public remote.
- Copy or symlink this folder into an
  application repo.
- Treat this as a replacement for repo
  `AGENTS.md` or repo `.agents/skills/`.
- Expect Cursor Cloud Agents to load
  these files. Promote team requirements
  into the repo harness or Team Rules
  before a Cloud run.

09 Practice

Put writing, tools, and cost. Not the repo.

The practice

shared.md holds how you like answers, which CLIs you use, and how you spend context. Do not put how to build this repo, a second copy of a repo skill, a global --no-verify rule, or tokens.

Why

Context is finite. Duplicating the repo in a personal file fights Precedence and wastes tokens every turn. Some Nuuly repos require --no-verify; others forbid skipping new lint. Follow the open repo instead of a global always or never.

Sources

Anthropic — context is a finite resource agents.md — repo-specific instructions stay in the repo

Example

example/home-agents/instructions/shared.md

## Tooling

- GitHub and Jira: `gh` and `acli`, not a

## Defaults

- Commits and PRs only when I ask.
- Branch names: follow this repo's
  CONTRIBUTING / AGENTS.md.
- Follow the **open repo's** commit-hook
  rules. Do not invent a global always
  or never `--no-verify`.

10 Practice

Three writing lines.

The practice

No preamble. No trailing summary of the diff. State each finding once. Keep those three in shared.md as the default writing style.

Why

Personal markdown is context, not a compiler. Short, repeated rules are followed more reliably than a long style essay. The Lab B load check is quoting Precedence, not adding a new closing sentence on every reply.

Sources

Claude Code — how you write instructions matters Anthropic — lean instructions

Example

example/home-agents/instructions/shared.md

## How I work

- Be short. No preamble. No trailing
  summary of the diff.
- State each finding once.
- Name tradeoffs in 1–2 sentences;
  I decide.

11 Practice

Main thread plans.

The practice

The chat you keep using is the orchestrator. Do not explore in the main loop. Spike unknowns in a subagent or a second session. Return a short finding. Use a cheaper model for mechanical work.

Why

Huge-file reads and API probing in the main thread fill the window you still need for the plan. Skills load more detail only when the task calls for it. A second session or subagent keeps that cost off the orchestrator.

Sources

Agent Skills — progressive disclosure Anthropic — diminishing returns on context

Example

example/home-agents/instructions/shared.md

## Context cost

- The main thread plans and decomposes.
  Do not explore in the main loop.
- Spike unknowns (API probing, huge-file
  reads) in a subagent or a second
  session. Return a short finding.
- New chat or `/clear` at phase
  boundaries.
- Cheaper model for mechanical work.

12 Practice

Same three checks for every product.

The practice

File on disk. Product lists the prefs. Smoke test: same PR prompt in an app repo (Goal / Ran / Doubt) and in this clone (What / Why this repo / Verify). Skip products you do not use. Android Studio Gemini is not Gemini CLI.

Why

A wrapper file can exist and still not load. Naming the file path in the quote prompt lets the agent Read it and fake a pass. Ask for the Precedence line from personal prefs. The real test is the second PR draft: does this clone’s What / Why this repo / Verify beat personal Goal / Ran / Doubt?

13 Practice

A personal skill is one job plus a script.

The practice

Repo skills stay in the clone. A personal skill is a step-by-step that is yours: SKILL.md tells the agent when to run; a script does the deterministic work. Do not re-author a repo skill under the same name.

Why

If the agent reimplements git worktree every time, the steps drift. The script is cheaper and repeatable. If you copy create-worktree into an application repo, you have forked a laptop layout into the team harness.

14 Lab A

10 minutes

Write personal prefs.

One file: ~/.agents/instructions/shared.md. Skip unused products. Work in an app repo that already has AGENTS.md.

mkdir -p ~/.agents/instructions ~/.agents/rules ~/.cursor/rules
cp templates/shared.md ~/.agents/instructions/shared.md
cp templates/creating-pull-requests.mdc ~/.agents/rules/creating-pull-requests.mdc
ln -sfn ~/.agents/rules/creating-pull-requests.mdc ~/.cursor/rules/creating-pull-requests.mdc
cp templates/agents.gitignore ~/.agents/.gitignore
git -C ~/.agents init

From the cloned lab/ folder. Keep Precedence first. Keep: no preamble; no trailing summary of the diff; state each finding once. The last two commands are required: copy agents.gitignore, then git init. Save only shared.md for cross-tool prefs. Do not copy-paste into each product.

Done when: shared.md starts with Precedence, ~/.agents/.gitignore exists, and git -C ~/.agents status works.
