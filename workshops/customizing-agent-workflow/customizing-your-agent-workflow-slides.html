03 The rule

Repo files win.

If a personal rule and a repo file disagree, follow the repo file.

03 / 41

[LIVE PATH — 0:05, Frame] Say this with me: Repo files win. If a personal rule and a repo file disagree, follow the repo file. That is the only rule you need to remember if you forget everything else today. Personal config is allowed. It does not override AGENTS.md, repo skills, repo hooks, or repo rules. Nothing automatically enforces that for markdown instructions. Repo hooks stop specific tool calls — push, deny lists, sandbox blocks. Markdown only advises. Both your personal file and the repo file load into the same context. The model can still follow the wrong one if your personal rule repeats or contradicts the repo. That is why every personal file starts with a Precedence block. In Lab A you will paste this at the top of your file — it is in section ten of handout.md and in lab/templates/personal-workflow.mdc. Read it to the room: Repo AGENTS.md, repo skills, repo hooks, and repo rules win. These lines are personal prefs for this machine. On conflict, follow the repo. The Precedence block tells the agent where personal prefs sit in the stack. It does not replace repo instructions. Do not copy branch rules, commit flags, or PR workflow from the repo into a personal file if the repo already owns them. Personal prefs should fill gaps — writing style, tool habits — not fight the harness. If your personal create-PR rule conflicts with repo AGENTS.md or a repo skill, remove the duplicate from personal or promote the team requirement into the repo. We verify with a smoke test in Lab C: ask what AGENTS.md says about commits and confirm the repo answer wins.

13 / 41
